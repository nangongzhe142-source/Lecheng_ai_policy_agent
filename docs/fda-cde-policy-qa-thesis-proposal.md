# 面向 FDA 与 CDE 医药监管政策动态更新的智能问答系统构建与评价研究

## 一、论文题目

备选题目：

1. 《面向 FDA 与 CDE 医药监管政策动态更新的智能问答系统构建与评价研究》
2. 《融合动态知识库与 RAG 的 FDA-CDE 医药监管政策智能问答系统研究》
3. 《面向医药监管政策依据追溯的 FDA-CDE 双源文本智能问答系统构建研究》

最推荐第 1 个。该题目同时体现 FDA/CDE、动态更新、智能问答、系统构建与评价，且没有夸大为自动审评或监管决策自动化。

## 二、核心基础方法

本研究的核心基础方法是 **检索增强生成（RAG）**，辅以 **动态知识库维护**、**依据追溯** 与 **人机协同质量控制**，构建面向医药监管政策的专业问答系统。

### 2.1 方法定位

**核心基础方法：RAG 检索增强生成 + 动态知识库 + 多模式检索 + 引用约束 + 人工复核闭环 + 系统评价。**

方法由三层构成：

| 层次 | 内容 | 在本研究中的作用 |
|------|------|------------------|
| **RAG 方法层** | 文档解析、分块、向量化、语义/全文/混合检索、重排序、LLM 生成、检索源引用 | 提高答案准确性、降低幻觉、支持依据追溯 |
| **动态知识库层** | 政策采集/导入、元数据标注、增量入库、版本记录、更新提醒 | 保障政策时效性，避免过期依据 |
| **人机协同层** | 回答自评、需复核标记、标注队列、批量对账、专家评价 | 控制误引与过度解释，支撑论文评价 |

三层关系：**RAG 是问答方法内核，动态知识库是时效保障，人机协同是风险控制与评价数据来源。**

### 2.2 RAG 技术路径

**索引入库路径：**

> 政策文档导入 → 文档解析（PDF/Word/HTML）→ 文本清洗 → 语义/章节分块 → Embedding 向量化 → 向量库 + 全文/关键词索引 → 元数据标注 → 增量入库

**问答检索路径：**

> 用户提问 → 检索召回（语义检索 / 全文检索 BM25 / 混合检索 / 关键词检索）→ Reranker 重排序（可选）→ LLM 基于检索片段生成 → 输出依据文件与段落 → 引用约束与风险提示 → 需复核判定

**动态更新路径（研究扩展重点）：**

> 政策源配置 → 定时监测/批量导入 → 更新识别 → 后台提醒 → 人工确认 → 增量入库 → 版本记录

**人机复核路径（已实现原型）：**

> 问答输出结构化自评（含「是否需要人工复核」）→ 追踪系统采集 LLM 运行记录 → 自动筛选需复核对话 → 推送标注队列 → 每日批量对账 → 专家标注与金标准积累

### 2.3 实验对比设计（方法配置）

论文实验将在同一 LLM 与知识库上，切换检索策略进行对比：

| 实验组 | 检索配置 | 说明 |
|--------|----------|------|
| 对照 A | 通用 LLM 直接回答 | 不挂载知识库 |
| 对照 B | 关键词/全文检索 + LLM | BM25 或关键词匹配 |
| 实验 1 | 向量检索 RAG | Embedding 语义召回 |
| 实验 2 | 混合检索 RAG | 向量 + 全文融合 |
| 实验 3 | RAG + Reranker | 召回后重排序 |
| 实验 4 | RAG + 引用约束 Prompt | 强制依据引用、证据不足拒答 |

## 四、研究背景与问题提出

FDA、CDE/NMPA、ICH 等监管机构持续发布药品研发、注册申报、临床试验、沟通交流、审评程序、说明书与标签等政策文件。这些文本数量多、专业性强、版本更新频繁，注册事务人员、研发人员和政策研究者需要快速、准确、可追溯地获取政策依据。

传统关键词检索依赖字面匹配，难以处理同义术语、跨文件关联和中美监管比较。大语言模型具备自然语言理解能力，但直接回答医药监管政策问题时容易出现幻觉、误引、过度解释和来源不可追溯。RAG 将检索与生成结合，为专业政策问答提供了可行路径。

此外，监管政策具有强时效性。若知识库不能动态更新，系统可能基于过期依据回答。同时，专业场景不能只依赖自动回答，还需要 **人机协同复核** 以控制质量。本研究在已有 RAG 原型基础上，面向 FDA-CDE 双源政策扩展动态知识库、依据追溯与系统评价，形成可验证、可复核的智能问答系统。

## 五、研究意义

理论意义：拓展监管科技、RAG 专业文本问答和医药监管信息化研究，补充动态知识库、依据追溯与人机复核闭环关注不足的问题。

实践意义：在已验证的原型之上，构建面向 FDA-CDE 的政策问答与复核系统，辅助注册事务、政策学习与依据定位。

技术意义：验证 RAG 多模式检索、引用约束、Reranker 与人工复核机制在高专业性监管文本中的适用性。

方法意义：形成“**RAG + 动态知识库 + 人机复核 + 对照实验**”的可复现研究范式。

交叉意义：体现 AI、NLP、药事管理、医药监管与信息管理的融合。

## 六、国内外研究现状

现有研究主要集中在智能问答、RAG、大语言模型、医学问答、法律政策问答和监管科技等方向。RAG 研究关注检索增强、幻觉控制、引用追溯；LegalBench 等基准推动政策/法律文本问答评价。

现有研究不足包括：

- 通用问答多，医药监管政策问答少；
- 静态知识库多，动态更新机制不足；
- 生成答案研究多，依据追溯与人工复核闭环不足；
- 系统原型多、系统评价少；
- 缺少面向 FDA-CDE 双源、含动态维护与复核机制的 RAG 问答研究。

## 七、研究目标

总体目标：在已有 RAG 原型基础上，构建并评价面向 FDA-CDE 医药监管政策动态更新的智能问答系统，实现政策知识库扩展、增量入库、多模式 RAG 检索、依据追溯、人机复核与对照实验。

具体目标：

1. 扩展构建 FDA 与 CDE/NMPA 医药监管政策文本库（由现有国内政策库方法论迁移）；
2. 设计政策采集/导入与更新监测流程，及人工确认机制；
3. 完善文档解析、分块、元数据标注与增量入库流程；
4. 构建监管政策问答评价集；
5. 基于 RAG（检索 + Reranker + LLM + 引用约束）实现问答，并衔接已有人工复核闭环；
6. 评价检索准确性、答案准确性、引用准确性、可追溯性、时效性与幻觉控制；
7. 分析典型错误并提出优化方案。

## 八、研究内容

研究内容一：FDA 与 CDE 医药监管政策文本来源与范围界定。聚焦上市前药品监管政策；当前原型以乐城先行区政策验证了入库与展示流程，论文扩展至 FDA-CDE。

研究内容二：监管政策采集与动态更新机制。设计定时监测、网页解析、新增识别、去重、元数据抽取、后台提醒、人工确认与更新日志；对接已有 `sync-policy-documents` 批量导入能力。

研究内容三：监管政策知识库构建与增量维护。PDF/HTML/Word 解析、清洗、分块、Embedding、向量库、全文索引、版本管理与增量入库。

研究内容四：监管政策问答任务与评价集设计。事实型、依据型、程序型、比较型、适用范围型、多跳型问题；标注标准答案与依据段落。

研究内容五：基于 RAG 的智能问答系统设计与实现。多模式检索、Reranker、引用约束 Prompt、风险提示、来源区分；集成 policy-regai 宿主平台与智能助手。

研究内容六：人机协同质量控制机制。延续已实现的「2+1」复核闭环：回答自评 → 自动入队 → 批量对账 → 专家标注 → 纳入评价集。

研究内容七：系统实验评价与误差分析。对比 LLM 直接回答、关键词检索、向量 RAG、混合 RAG、RAG+引用约束、RAG+Reranker。

研究内容八：应用边界、风险控制与优化。幻觉、误引、来源混淆、政策过期、过度解释；人机协同边界。

## 九、研究问题

1. 医药监管政策文本如何组织为适合 RAG 的动态知识库？对应第 4 章。
2. 如何实现公开政策的采集、更新识别与人工确认入库？对应第 5 章。
3. 如何在人工确认后完成增量入库与版本管理？对应第 5 章。
4. 医药监管政策问答有哪些类型，如何构建评价集？对应第 6 章。
5. RAG 多模式检索能否提高准确性、可追溯性与时效性？对应第 7-8 章。
6. 与 LLM 直接回答相比，动态知识库 RAG 在哪些方面更优？对应第 8 章。
7. 系统会出现哪些典型错误，人机复核能否识别与修正？对应第 8 章。
8. 如何设计人机协同与风险控制机制？对应第 9 章（可重点写已实现的复核闭环）。

## 十一、技术路线

文字流程图：

> 政策源配置 / 批量导入 → 更新识别 → 后台提醒 → 人工确认 → 文档解析 → 分块 → 向量化 → 增量入库 → 用户提问 → 检索召回 → 重排序 → LLM 生成 → 来源引用 → 自评/需复核标记 → 标注队列 → 专家评价 → 实验优化

关键步骤：

1. 配置 FDA、CDE/NMPA、ICH 政策源（扩展）；复用已有批量导入脚本；
2. 定时任务或手动同步监测变化；
3. URL、标题、日期、文件哈希判断新增/更新；
4. 后台提醒与人工确认；
5. 解析 PDF/HTML/Word，清洗与分块；
6. Embedding 向量化 + 全文/关键词索引；
7. 增量入库与版本记录；
8. 用户通过政策平台或助手提问；
9. 切换语义/全文/混合/关键词检索；
10. 可选 Reranker；
11. LLM 生成 + 引用约束 + 风险提示；
12. 结构化自评输出需复核标记；
13. 自动推送标注队列 + 每日对账；
14. 自动与人工评价优化。

## 十三、研究方法

**核心基础方法：RAG 检索增强生成 + 动态知识库 + 人机协同评价。**

文献研究法：梳理 RAG、问答系统、监管科技、药品审评研究。

系统设计与实现方法：在已有原型上扩展 FDA-CDE 数据域与更新机制。

文本挖掘方法：政策解析、清洗、分块、元数据抽取。

知识库构建方法：向量索引、全文索引、增量入库。

配置对比实验法：切换检索模式与 Reranker，比较 RAG 配置效果。

人机协同评价法：利用已实现的复核闭环收集需复核样本，专家标注支撑 faithfulness 与 error_type 分析。

比较分析法：FDA 与 CDE 政策文本及问答结果比较。

案例分析法：典型问答与错误案例。

## 十四、评价指标体系

**政准确率、召回率、去重准确率、元数据抽取准确率、入库成功率、更新延迟、版本完整性。

**检索指标（分检索模式统计）：**

- Recall@k、Precision@k、MRR、Top-k 命中率、来源机构识别准确率。

**问答指标：**

- 答案准确性（1-5）、依据引用准确性、faithfulness、幻觉率、完整性、可追溯性、FDA/CDE 来源区分正确率、意图匹配度。

**人机复核指标（对接已实现闭环）：**

- 需复核识别准确率（自评 vs 专家）；
- 标注队列入队成功率、对账一致率；
- 复核后答案修订率；
- 复核样本中的错误类型分布。

## 十五、实验设计

实验一：政策导入与更新检测（扩展 FDA-CDE 后开展）。基准：人工核验；指标：发现率、入库成功率。

实验二：检索效果实验。比较关键词/全文、向量、混合检索 ± Reranker；指标 Recall@k、MRR 等。

实验三：RAG 问答效果实验。六组对照（见 2.3 节）。

实验四：人机复核效果分析。分析需复核样本中的幻觉、误引、来源混淆；比较复核前后 faithfulness。

实验五：错误分析。检索错误、生成错误、引用错误、政策过期、过度解释。

样本规模：文档 100-300 份、问答 200-500 条；硕士最低可行 80-150 份文档、150-200 条问答（含已有 41 份作为起点）。

## 十六、论文创新点

## 十八、风险与规避方案

1. FDA/CDE 范围过大 → 限定上市前注册审评政策。
2. 网站结构变化 → 模块化采集 + 保留批量导入（**已验证**）。
3. 爬虫合规 → robots、低频、仅公开文件。
4. 术语不一致 → 术语映射表。
5. PDF 解析差 → 优先 HTML/可复制 PDF；调整分块策略。
6. 标准答案主观 → 标注规则 + 双人校验 + 复核队列金标准。
7. 专家不足 → 小规模专家 + 研究生交叉 + 自动指标。
8. RAG 幻觉 → 引用约束 + 证据不足拒答 + **人工复核**（**已实现管道**）。
9. 被质疑工程报告 → 突出方法、评价集、对比实验、复核闭环与误差分析。
10. 原型域与论文域不一致（乐城 vs FDA-CDE）→ 明确写“方法在乐城语料验证，FDA-CDE 为扩展评价对象”，避免声称 FDA 数据已入库。
11. 政策问答≠监管决策 → 明确不替代审评员。
